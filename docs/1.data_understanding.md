# Data Understanding — Spotify Streaming History

This document summarizes the initial data-quality and structure checks performed before starting exploratory analysis. It reflects the dataset as loaded from `data/spotify_history.csv`.

## Dataset Overview

- **Rows:** 149,860
- **Columns:** 11
- **Date range:** 2013-07-08 to 2024-12-15 (~11.5 years of listening history)

## Column Types

| Column            | Type                                   |
| ----------------- | -------------------------------------- |
| spotify_track_uri | str                                    |
| ts                | datetime64[us] (converted from string) |
| platform          | str                                    |
| ms_played         | int64                                  |
| track_name        | str                                    |
| artist_name       | str                                    |
| album_name        | str                                    |
| reason_start      | str                                    |
| reason_end        | str                                    |
| shuffle           | bool                                   |
| skipped           | bool                                   |

`shuffle` and `skipped` were inferred correctly as booleans on load. `ts` required conversion from string to datetime before any time-based analysis.

## Missing Values

| Column            | Nulls |
| ----------------- | ----- |
| reason_start      | 143   |
| reason_end        | 117   |
| All other columns | 0     |

Missing values total ~0.1% of rows — negligible. No rows dropped; nulls in `reason_start`/`reason_end` can be left as-is or filled with `"unknown"` depending on the needs of downstream analysis.

## `reason_start` / `reason_end` Distributions

**reason_start** (top values): `trackdone` (76,655), `fwdbtn` (53,793), `clickrow` (11,228), `appload` (3,729), `backbtn` (2,205), `playbtn` (1,458), plus a long tail of rarer values.

**reason_end** (top values): `trackdone` (77,194), `fwdbtn` (53,470), `endplay` (10,119), `logout` (4,367), `backbtn` (2,182), `unexpected-exit-while-paused` (1,725), plus a long tail.

`fwdbtn` accounts for ~36% of all plays by both start and end reason — a strong initial signal about forward-skipping behavior.

## Understanding the `skipped` Flag

Initial assumption: `skipped == True` corresponds to plays ended via `fwdbtn`. Cross-tabulating `reason_end` against `skipped` showed this is **not** the case:

- Only **5.25%** of all plays are flagged `skipped == True`.
- Of the ~53,470 `fwdbtn`-ended plays, only ~5,451 (~10%) are flagged as skipped.
- `endplay` has a disproportionately high skip rate (~20%) relative to its overall frequency.
- `trackdone` is almost never flagged skipped (22 of 77,194), as expected.

**Finding:** Grouping `ms_played` by `skipped` shows skipped plays have a substantially lower median play duration than non-skipped plays (a difference of roughly 145,000 ms, ~2.4 minutes). This indicates **`skipped` is a duration-based signal, not simply "the user pressed the forward button."** A play can end via `fwdbtn` without being short enough to count as a skip, and conversely other end-reasons can still register as a skip if the play duration was short.

Out of all 53,470 plays that ended because the user hit forward (48019 + 5451), only 5,451 of them were also flagged skipped == True. The other 48,019 — the vast majority — ended via forward button but were not counted as skipped.

reason_end == 'fwdbtn' tells you which button ended the play.
skipped tells you how quickly the play ended, regardless of button.

That's why the two columns disagree so much: they're measuring two different things — the mechanism (reason_end) vs. the outcome/duration (skipped) — and they only partially overlap.

This distinction matters for any downstream analysis of skip behavior — `reason_end == 'fwdbtn'` and `skipped == True` should be treated as related but distinct signals, not interchangeable.
